How this will look

Six sample screens built against one token file, so the design system can be judged by looking at it rather than by reading hex values. Every sample links tokens.css and contains no colour of its own — if a screen needs a colour the system does not have, that gap shows up here rather than months later as a hardcoded value in a component.

These pages open in light, whatever your OS is set to. The Toggle theme button flips the dashboard and auth pages to dark — the POS deliberately will not move, because the till is a device: its surface is a property of the hardware on the counter, not of the viewer's preference. The POS is light and pinned in both themes, and it pins its complete palette — grounds, inks, status and all. Pinning only the grounds put dark-theme ink on the white key face at 1.21:1, which is the original bug mirrored.

Three surface states, one vocabulary

Token names are identical in all three states; only their values differ. That is what lets a component be written once: it never names a colour, only a role, so text-ink is correct on every surface and simply resolves differently inside the till.

State Selector Pairs Failures Tightest
Light :root 182 0 4.55
Dark prefers-color-scheme + [data-theme="dark"] 182 0 4.62
POS [data-surface="pos"] — light, pinned in both themes 182 0 4.60

Computed by WCAG relative luminance against the 4.5:1 floor; boundaries clear 3:1 per WCAG 1.4.11. One consequence of the light till, measured: a white key on the POS ground is only 1.22:1, so elevation alone cannot carry its edge — every key takes a --c-control-line border at 4.73, or it fails WCAG 1.4.11.

Two rules to read the samples by

Colour never carries meaning alone. Every status is a colour and a glyph — item ◇NEW, ▲SENT, ✕VOIDED; sync ◆offline. Roughly one man in twelve has red-green colour vision deficiency, and a counter screen is read under glare.

Money is always mono, tabular-nums, right-aligned — so digits line up down a column and a cashier can scan a check without reading it. Negatives carry a leading − and the danger colour, never colour alone. Every amount in these samples is a static display string: the UI never does money arithmetic and never rounds.

What these are not

Not application code — nothing here is imported by src/. Not a component library — the real primitives are src/lib/components/ui/. And not a commitment to POS layout: samples 04 and 05 show the grammar, not a screen size, because the open decision about whether there is one shared counter device or a second registered terminal is what sets the target hardware, and it is unanswered.
